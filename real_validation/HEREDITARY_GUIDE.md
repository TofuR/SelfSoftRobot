# Hereditary / Analytic B 实验操作指南

2026-09-10：已按采集 App 的设备连接与腔道控制习惯重整为四页流程。打开 [带红圈编号的 HTML 操作手册](../workspace/runs/analysis/hereditary_deployment/deadline_20260910_002/guide.html)。独立 ZIP 内为 `HEREDITARY_GUIDE.html`，截图内嵌，无需网络。

## 启动

```bash
python -m real_validation.main
```

Windows 也可用 `run_gui.bat`。独立目录安装 `requirements.txt`，真实 USB/串口另装 `requirements-hardware.txt`；无需 `src/` 或 `real_capture/`。旧 OpenLoop 在 `--legacy-openloop` 兼容入口保留。

## 1 设备模型

加载同名 `hereditary.npz + hereditary.json`，检查紧凑两行六腔映射，默认 `[0,1,1,2,2,3]`。六腔必须覆盖四个输入，共享输入同压。模型加载只检查模型和配置，不发压力，不创建准备动作历史。

选择全 Mock 或真机验证，分别连接组1、组2与相机；连接内部校验配置，无需额外应用 profile。真实端口示例 COM3、COM46，按设备电脑实际设置。高级栏放 backend、波特率、从站、相机数量/serial 与保存位置。动作驱动 Mock 相机要求先加载模型；两组阀与真机使用同一连接入口。未连接的腔显示未知。

相机驱动可选 **自动 / RealSense SDK / 普通摄像头 UVC/OpenCV**。自动模式优先枚举 SDK 支持的 RealSense；未发现时使用 UVC 设备索引（默认 0，多台可在高级栏写 0,1）。RealSense 需要 `pyrealsense2`，其他兼容型号需支持配置的彩色流；同品牌不代表所有型号兼容。指定 RealSense 或 serial 后失败就报错，不换到其他设备。UVC 使用操作系统视频驱动，不需要 RealSense SDK。采集中途不会自动切换相机。两条路径目前都只保存彩色图像，不保存深度图。

第一页恢复 **NDI 可选连接**：backend、串口、探头数、连接/断开。未连接、选择 Disabled 或 NDI 报错都不阻止部署/执行；已连接的数据只作为独立评价流，不输入模型。

## 全局六腔控制

点击相机上方常驻 **六腔控制** 打开非模态窗口，主界面仍可操作。

- 表格给出每腔输入、目标、ACK 确认下发值、min/max、rise/fall。ACK 下发值不是实测腔压。
- 共享输入目标联动；每腔限制独立，与同输入其他腔及模型包取交集。速率 0 表示不额外收紧，模型包限速仍生效。
- **应用目标与限制**：整套校验后生效。若范围排除当前下发压力，先调入新范围再收紧。运行时有效编辑在下一拍采用。
- **手动调压 / 接管**：独立时钟限速跟随目标，不依赖录制或部署。未连组及缺少所需阀组的共享输入不能操作。
- **结束调压（保持）**、关闭窗口或 Escape 均停止手动发送，保持末压；**全部归零**独立。
- 自动执行中接管先停止旧发送器、处理在途 ACK，再开始手动。旧计划不能恢复。已部署的手动动作仍更新同一个模型状态；连续历史与相机不变时不重做几何对齐。

连接不会恢复上次的非零输出。映射/限制与设备配置保存；重新加载模型后的映射仍需核对实际接管。更换映射或模型驱动虚拟相机的模型前先断开相机。

## 2 部署预热

先用六腔工具调到希望的初压，结束调压保持，然后只按以下顺序操作：

1. **自动提取当前完整形状**：确认当前保持压力的 ACK，从此建立部署需要的时间/命令缓冲，获取新图像；不要求零压。
2. 检查冻结画面上的黄点、BASE/TIP；可拖动修正、交换端点或手动重画。压力或相机变化后重新提取。取消草稿不改变气压。
3. **确认形状并部署预热**：先匹配 base、旋转和统一尺度，再固定相机变换，用完整形状约束修正 p/h。已有有效状态就延续；否则采用训练一致的当前输入平衡先验 `p=h=e(u)`，不假装真实物理记忆已知。
4. 系统保持当前压力，按实际时间推进状态，连续用新图像修正。默认最短 2 s、最多 20 s、连续 8 帧；覆盖 ≥75%、残差 ≤3 px、帧间估计形状变化 ≤1 px 才就绪。高级栏可调整。超时或证据不足不放行。

初始形状要求全臂可见，多个较大碎片、空图、裁切会拒绝自动提取；没有从虚拟设备隐藏形状初始化。确认前 RMS >8 px 不放行。单个姿态不能唯一辨识相机与全部记忆；这里是有先验约束的部署估计，不是重新训练权重。相机透视或实际移动需重新对齐，当前不能自动识别所有相机运动。

部署通过保存快照：模型哈希、映射/限制、变换、压力、状态、时间及质量。没有“首次初始化”和“重开历史段”两套按钮。长期保持仍影响 Maxwell，play 不会因等待自动清空。

## 3 目标规划

从已对齐 base 按住左键连续画到 tip。起点偏差超过 5 mm 拒绝。整条中心线参与拟合，排除固定 base 计算平均/最大误差。

默认平均容限 **2 mm**、最大节点 **4 mm**，均可调整。无需知道应走几步：外层尝试 10、20、40、60、80 等长度，受模型最大时域与 15 s 初始搜索预算约束；复用候选，必要时补充限速终态压力搜索。返回首个预测达标候选，不能保证全局最短。未达标显示“当前搜索未达标”，不能执行，不等于证明目标不可达。

点击 **初始规划参数…** 打开非模态弹窗：平均/最大节点容限、长度上限、总预算（默认 15 s）、每个长度 B 迭代上限（24）、终态优化评估上限（30）和搜索步长（20）。修改立即生效并使旧计划失效；计算/执行期间锁定。初始规划的总耗时及每个尝试长度耗时显示在预览并保存。预算在迭代间检查，单次调用可能略超预算；终态求解器评估上限不含数值差分的额外调用。

**播放模型预测 / 时间轴**显示每一步紫色预测和六腔压力曲线、数值。青色为当前估计，红色为目标，黄色为形状草稿。整体管身是中心线按模型半径扩展，可调透明度，不是隐藏区域的图像测量。

规划不发动作。执行前校验版本、映射、限制、相机和当前持压状态；原预览若变化明显或不再达标，重新规划预览，不静默换轨迹。当前不包含避障。

## 4 执行记录

确认预览后勾选允许执行，再开始实验运动。真实或虚拟相机均可开启 **软件遮挡测试**。表格每行一个矩形，设置 x/y/宽/高（原图百分比）和灰度 0–255，可添加最多 16 个区域；点击应用后生效，执行期间锁定参数。整图遮挡为 0/0/100/100。它只修改图像副本，算法不接收矩形位置；真实物理遮挡无需手画区域。初始化前关闭此项。

每步为：压力 → 两组 ACK → 从实际 applied6 修复合法后缀 → 命令后的新图像 → 可信侧边校正 p/h → 重放图像后的已确认命令 → Analytic B 修订剩余动作。每次运动有独立 ID，与部署快照关联，保存动作、状态、后缀、计算时间及原图。

连续无新帧/可信边缘的停止门限默认 3 次，可在第四页设为 1–10 次。缺失期间仅按模型与合法后缀运行，不进行图像状态修正/后缀优化；达到门限停止归零，使部署就绪失效。不会无限搜索、自动试探压力或自动恢复旧计划。即使短计划在门限前结束，只要结束时仍缺失反馈，也会撤销就绪并标记未确认，不能直接继续规划。全遮挡下不能保证稳定跟踪，也不能确认到位；有纹理的遮挡物仍可能产生误匹配。指令失败同样停止归零。反馈采用独立状态快照，截止时间为本次发令时间 + 模型 dt − 3 ms 预留。按时完成才一起提交 p/h、历史和后缀；超时整次丢弃，保留实际 ACK 后修复的合法后缀。后台最多一个反馈任务，未结束时跳过新任务，不积压，也不能在迟到后修改实时模型。默认连续 10 次不能及时提交反馈停止归零，第四页可调为 1–100。

始终选用 ACK 后接收的新帧。第四页 **发令后额外等图** 默认 0 ms，可按设备需要调大，但会挤占当前周期的反馈预算；不再固定多等 50 ms。图片写盘使用有容量上限的后台队列，积压或保存失败会报告失败。至少间隔模型 dt 发令，不突发补发。此为 Python 软期限调度；相机、阀通信、GIL 和操作系统调度仍可能使实际间隔超过 dt，不能宣称硬实时 100 ms。最后一步仍超时/缺反馈则撤销就绪。

**停止运动（保持当前压力）**与手动接管正常停止旧轨迹。**中止并全部归零**为另一入口。正常结束保持末压，继续观测和显示漂移，不自动启用额外的目标保持控制器。

分别看指令是否完成、模型全形状目标差、可信可见边缘到目标管身的差。后者只覆盖已有边缘，遮挡部分不宣称实测到位。“局部证据缺失”也可能来自光照、预测或对齐误差，覆盖率不是遮挡概率。

目前真实接口只支持正压，当前部署包 0–150 kPa；**实际负压不支持**。服务器没有连接设备，虚拟测试不证明实机通信或控制精度。

## 执行结果文件

每次运动在 `runs/hereditary/<run>/executions/<id>/` 独立保存，正常结束、普通停止、无图像/无边缘失败均有记录：

| 文件 | 内容 |
|---|---|
| `initial_plan.npz` | 初始完整动作（模型单位和六腔 kPa）、参考形状 mm、状态与版本 |
| `timings.csv` | 每步发令间隔/偏差、ACK、等图、预处理、反馈预算/等待/完整计算时间、边缘/观察器/B 耗时、写盘入队、循环耗时、提交状态 |
| `steps.jsonl` | 每步修订前、实际 ACK 后合法后缀、最终采用后缀（模型单位与 kPa）、状态/版本及采纳或跳过原因；故障步也记录 |
| `feedback_jobs/*.json` | 独立候选与真正计算完成时间，包括迟到结果；只是提案，是否采用以 steps.jsonl 为准 |
| `commands.csv` | 请求六腔 kPa、实际下发六腔 kPa、命令 ID、发送/ACK 时间与状态；故障归零也记录 |
| `raw/camN/*.png` | 每个控制步保存各相机最新原图；反馈主相机为此次真正选用的原帧，辅助相机是否在命令后有新帧明确标记 |
| `frames/*.png` | 真正送入观察器的主相机图像，包括人工软件遮挡；最后的失败帧也保留 |
| `samples.csv` | 步号、相机、图像时间、对应命令、命令后时间差、新鲜标记、图像路径、遮挡参数、后台实际写图耗时 |
| `ndi.csv` | 执行期间全部 NDI 样本，逐探头保存位置/姿态/quality/valid；失锁保留 NaN，未连接时仅表头 |
| `frame_ndi.csv` | 每张图像对应的最近且不晚于图像的 NDI 时间、年龄，以及是否在 200 ms 内；无数据留空 |
| `metadata.json` | 设备模式与驱动、部署 ID、执行状态、遮挡配置、NDI 连接/样本信息 |

`feedback_wait_ms` 是控制线程等待时间，超时任务的完整耗时在随后写出的提案文件中；未完成不填 0。`metadata.json` 记录关闭时尚未写完的反馈提案，进程提前结束可能无法得到这些任务的完整耗时。`cycle_ms` 到本步审计写入前为止；真实的命令间隔还包含调度和日志开销。

上级 `events.jsonl` 继续记录模型状态、每步反馈与剩余动作修订。压力是命令及 ACK，不是实测腔压；NDI 是独立测量。时间采用主机 monotonic 接收时间，多相机并非曝光同步，NDI 的时间接近也不代表设备硬件同步。NDI 缓冲最多保存 60000 条，元数据给出最早保留时间，便于检查记录范围。

## A 与 B 的实测比较

原高变化 80 帧窗口（182519，2198–2277，56×56 固定方块），以校正后模型预测和录制参考形状比较，排除固定 base：

| 指标 | Cached A | Analytic B |
|---|---:|---:|
| 整段平均节点距离 mm | 0.7474 | 0.7064 |
| 最后一帧平均节点距离 mm | 0.5723 | 0.3668 |
| 最后一帧 tip 距离 mm | 1.0696 | 0.1712 |
| 后缀接受次数 | 16/79 | 78/79 |
| 反馈计算 P50 / P95 / max ms | 22.1 / 27.7 / 33.8 | 39.8 / 48.1 / 54.6 |

B 在此窗口的差异更小，但原图不会响应修订后的动作，因此不是实机控制精度对照。

A 的拒绝中，7 次为缓存与非线性 rollout RMS 失配 > 0.5 mm，56 次为投影及回溯后，坐标 MSE 没有下降至少 `1e-8 mm²`；回溯比例 1、1/2、1/4、1/8，修正信赖范围 0.08 模型单位。拒绝保留上次合法后缀，图像状态观察器仍会更新，故接受率不等于控制成功率。

B 另一次独立进程计算 P95/最大为 58.5/139.2 ms，不能保证所有周期 < 100 ms；以上不含相机曝光、等新帧、阀通信和写图。完整来源见 [回放验证记录](../docs/experiments/partial_observation_replay_validation.md)。

## 复现与导出图解

```bash
# 无显示服务器设置 QT_QPA_PLATFORM=offscreen
python -m real_validation.tools.hereditary_smoke \
  --bundle real_validation/checkpoints/hereditary_current/hereditary.npz \
  --out path/to/new_mock_trial
```

操作实际 GUI 与 Qt ACK 桥接，输出未标注和红圈标注截图、自包含 `guide.html`、`summary.json`、事件日志和原图。模型虚拟相机用同一冻结模型，机器结果明确 `physical_hardware_tested=false`。

打包：

```bash
python -m real_validation.tools.package_hereditary \
  --bundle path/to/hereditary.npz --guide path/to/new_mock_trial/guide.html \
  --out path/to/new_workbench.zip
```

导出训练 checkpoint 的方式不变，见 `scripts/evaluation/export_hereditary_deployment.py --help`。包内动作 kPa 尺度已包含 checkpoint 的归一化因子，不要重复乘尺度。
