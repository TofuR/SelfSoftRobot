# 轻量软臂分割微调：YOLO26 候选与离线验证

2026-09-11 核对官方资料并准备离线训练。本轮不接入规划前外力摆动实时跟踪，不改变现有 App 的感知/控制线程。

## 候选与公开速度

[Ultralytics 模型目录](https://docs.ultralytics.com/models/)当前推荐 YOLO26 用于新项目，YOLO11 为成熟替代。本轮选直接输出 mask 的 YOLO26n-seg / YOLO26s-seg，不采用检测框再接 SAM 的串联。

[官方分割表](https://docs.ultralytics.com/tasks/segment/)（640 输入）：

| 模型 | COCO mask mAP50–95 | CPU ONNX ms | T4 TensorRT10 ms |
| --- | --- | --- | --- |
| YOLO26n-seg | 33.9 | 53.3 ± 0.5 | 2.1 ± 0.0 |
| YOLO26s-seg | 40.0 | 118.4 ± 0.9 | 3.3 ± 0.0 |

这是官方环境与 COCO 指标，不是软臂实测精度，也不包含本 App 的相机传输、mask 后处理、中心线与控制更新。选择 n 优先测试 CPU/轻量部署，s 作为精度/速度对照；不能先验保证 s 对软臂更准。分割本身不使用 5/10 Hz 动作历史，无需按控制模型频率拆两个分割数据集。

官方 PyPI 版本固定为 `ultralytics==8.4.146`。来源权重为官方 assets `v8.4.0/yolo26{n,s}-seg.pt`，下载 URL、SHA256 位于 `workspace/models/pretrained/yolo26/source_manifest.json`；独立环境 `workspace/venvs/yoloseg_20260911` 复用已有 torch，未修改部署环境。

## 数据与质量边界

已配对 9 条同平台序列的原图与最终 SAM2 mask。裁剪 mask 为 300×300，原图 640×480；必须先加回 crop 原点 (220,68)，再用原图尺寸归一化为 YOLO 多边形。不能把裁剪坐标直接配给整幅原图。

按完整原序列分组：182253 为验证，182519 为测试，其余 7 条为训练。每序列最多均匀取 1500 帧，避免最长序列支配训练。没有相邻帧随机混入不同集合；这些仍是同一相机背景域，不代表 D415 新背景泛化。

最终训练 6404、验证 1097、测试 1405 张。另有 292 张因原 mask 明显断裂/孔洞且无法保持 ≥0.98 的多边形还原 IoU 而排除，保留清单。抽看六个受影响序列的拒绝样例发现前景气管遮挡导致部分条带缺失；没有填补遮挡当完整真值，也没有直接把最大碎片当整臂。排除比例触发自动检查后，经本轮图像审阅记录为 clean-mask 子集放行。指标须标明质量过滤；困难帧留作后续单独评估。原 SAM mask 是伪标签，不是独立人工真值。短零压校准序列183526没有同标准最终 mask，未纳入。

数据清单、坐标信息、标签 SHA 与检查图均在 study 中。两项针对性测试覆盖裁剪坐标恢复及断裂/越界拒绝。

## 操作语义澄清

“末端调整余量 0”是额外 0 步，不是 0 kPa。正余量初始化为保持末条压力的动作；只有主动归零/故障停止逻辑才会发零压。

首次确认部署包含相机几何与尺度拟合、当前模型状态估计和连续图像预热，控制权重不训练。希望在哪个初压启动，可先手动调压、稳定保持、提取并确认。配准后再调压，则结束保持后复用配准重新预热；不能声称只有首种顺序才准确。

没有计划且空闲时，当前 GUI 可用局部边缘更新模型；手动调压期间只按已确认动作预测。已生成计划后暂停保持期图像校正，避免破坏已预览计划的版本。因此应保持实验条件，明显扰动后重新规划；不是预热完成就必须抢时间操作，也不承诺目前可跟随任意外力。
