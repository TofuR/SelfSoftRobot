# 软体机器人自建模 — 当前模型、实验结果与后续规划

> 2026.04.28 — 项目进展汇报

---

## 一、项目目标

**让软体机器人仅通过观察自身的外部图像（2D 相机拍摄），学会预测自身在不同驱动输入下的三维形态。**

原始构想源自 NeRF 思路：
```
输入: (3D空间点坐标, 模型参数/驱动信号)
输出: (该点的可见度, 该点的密度)
训练信号: 2D 相机图像
```
即用体渲染 (Volume Rendering) 把 3D 场景投影到 2D，用 2D 图像做监督。

## 二、模型演进路线

### 2.1 第一代: MSTNF — 直接 NeRF 思路

```
驱动信号序列 → MultiScaleEMA → 物理状态向量 (128维)
空间查询点 (x,y,z) → 位置编码 → 与物理状态拼接 → 5层MLP → [可见度, 密度]
体渲染 → 2D图像 → 与GT图像对比 → 反向传播
```

**问题**: 模型需要同时学习"软体机器人在哪"和"它长什么样"，搜索空间太大。变形场 MLP 产生高频振荡，骨架不光滑。

### 2.2 第二代: C-MSTNF 系列 — 典范场 + 变形场

引入"典范场"思路（借鉴 D-NeRF）：
```
静态典范场: 学习静止状态下机器人的外观
变形场: 学习驱动信号引起的三维位移
组合: 典范场(变形(空间点, 驱动信号)) → [可见度, 密度]
```

三个变体:
| 模型 | 时序编码 | 变形场 | 结果 |
|------|---------|--------|------|
| C-MSTNF | MultiScaleEMA | 5层MLP + 位置编码(n=6) | 高频跳变 |
| ODE-CMSTNF | Neural ODE | 同上 | ODE改进时序，空间问题不变 |
| Smooth-CMSTNF | MultiScaleEMA | Spectral Norm MLP | 尖端发散(SN限制大变形) |

**根本问题**: 变形场用 MLP + 高频位置编码映射到 3D 位移，ReLU 的分段线性 + 高频振荡 → 骨架不光滑。

### 2.3 当前模型: MS-SCNF — 骨架先验 + 骨架条件密度场

**核心转变**: 不再让网络隐式学习变形，而是**直接输出三维骨架坐标**，再基于骨架计算密度。

```
                        ┌─── SkeletonHead ──→ coarse骨架(4节点)  ─┐
                        │                                      ├── 多尺度3D loss
驱动序列(20帧) → EMA → ┼─── SkeletonHead ──→ medium骨架(10节点) ─┤
                        │                                      ├── 3D MSE loss
                        └─── SkeletonHead ──→ fine骨架(31节点)  ─┘
                                              │
                                              ↓
                            SkeletonConditionedDensity:
                            空间点 → 计算到骨架距离 → 距离编码 + 位置编码 → MLP → [可见度, 密度]
                                              │
                                              ↓
                            体渲染 → 2D图像 → 与GT图像对比 → 渲染loss
```

**为什么这样设计**:
1. **骨架是连续的**: 输出 (31, 3) 坐标序列，天然光滑，不需要正则化
2. **密度由距离决定**: 离骨架近 → 密度高，远处 → 密度趋零。`exp(-dist²/2σ²)` 天然无穷阶可导
3. **3D GT 直接监督**: 仿真器提供 31 个节点的精确坐标，比间接的 2D 渲染 loss 更有效
4. **多尺度训练**: 先学粗骨架(4节点)，再逐步精细到 31 节点

## 三、MS-SCNF 各组件详解

### 3.1 MultiScaleEMA — 时序编码器

```python
输入: 动作窗口 action_window (B, 20, 2)  — 过去20帧的2个驱动扭矩
输出: 物理状态 physics_state (B, 128)

原理: 4个不同衰减率的指数移动平均(EMA)
  α₁, α₂, α₃, α₄ — 可学习的衰减率(sigmoid约束到(0,1))

  对每个尺度 s:
    state_s = 0
    for t in [0, 1, ..., 19]:
      state_s = α_s * state_s + (1 - α_s) * action[t]
  → state_s 捕捉不同时间尺度的历史信息

  快衰减(α小): 捕捉最近几帧的变化
  慢衰减(α大): 保留长期趋势

  4个状态拼接 + 当前动作 + 速度 → MLP → 128维物理状态
```

**局限**: EMA 是线性算子，无法捕捉非线性迟滞（加载/卸载不对称）。

### 3.2 SkeletonHead — 骨架回归头

```python
输入: physics_state (B, 128)
输出: {coarse: (B, 4, 3), medium: (B, 10, 3), fine: (B, 31, 3)}

结构:
  共享 trunk: Linear(128→256) → ReLU → Linear(256→256) → ReLU
  ├── coarse_head: Linear(256 → 4×3=12)
  ├── medium_head: Linear(256 → 10×3=30)
  └── fine_head:   Linear(256 → 31×3=93)
```

31 个节点沿杆体均匀分布，从 base (z≈0) 到 tip (z≈0.5m)。输出直接是三维坐标 (x, y, z)，单位米。

### 3.3 SkeletonConditionedDensity — 骨架条件密度场

```python
输入:
  - query_points (N_rays, n_samples, 3) — 沿射线采样的3D点
  - skeleton (B, 31, 3) — 预测的骨架节点

处理流程:
  1. 计算 query_point 到每段骨架线段的距离 d
     → point_to_segment_distance (可微)
  2. 对距离做正弦位置编码: PE(d) → 13维
  3. 对查询点做位置编码: PE(x,y,z) → 28维
  4. 拼接 → 41维 → 5层MLP → [visibility, density] (2维)

直觉:
  - 离骨架近 → d小 → 编码值特殊 → 密度高
  - 远离骨架 → d大 → 密度趋零
  - 位置编码提供额外的空间位置信息
```

### 3.4 体渲染 — 从 3D 密度到 2D 图像

```python
1. 从相机发射射线 (100×100 = 10000 条)
2. 沿每条射线采样 48~64 个 3D 点
3. 每个点查询 density → (visibility, density)
4. OM_rendering:
   α = 1 - exp(-softplus(density))
   pixel = Σ(α × visibility)  # 沿射线累积
5. 得到 100×100 的渲染图像
6. 与真实图像比 MSE → 反向传播
```

### 3.5 两阶段训练

```
Phase 1 (骨架学习, ~50 epochs):
  loss = MSE(pred_skeleton, GT_3D_positions) + smoothness_reg
  只训练 temporal + skeleton_head, density 冻结

  这里用了仿真器的 3D GT！这是模型精度高的关键，也是
  "真正自建模"需要去掉的依赖。

Phase 2 (联合训练, ~200 epochs):
  loss = 3D_skeleton_loss + 0.5 × rendering_loss
  同时训练全部组件
```

| 指标 | MS-SCNF (Phase 2) | 说明 |
|------|-------------------|------|

| **Tip Error** (末端误差) | **0.1085 m** | 末端偏移10.8cm |
| **PSNR** (渲染质量) | **19.39 dB** | 图像重建质量 |
| 逐轴误差 X/Y/Z | 0.018/0.016/0.014 m | 误差分布较均匀 |

### 4.2 全部模型横向对比

| 方法 | MNE (m) | Tip (m) | X err (m) | Y err (m) | Z err (m) | Z轴误差占比 |
|------|---------|---------|-----------|-----------|-----------|------------|
| MS-SCNF (有3D GT) | **0.0646** | **0.1085** | 0.018 | 0.016 | 0.014 | 28% |
| Exp2 Model A (3D GT) | 0.0611 | 0.1582 | 0.042 | 0.031 | 0.020 | 22% |
| **Exp1b (渐进2D+先验)** | **0.1535** | **0.2069** | 0.060 | 0.037 | 0.110 | **72%** |

| Exp2 Model B (2D only) | 0.3028 | 0.5534 | 0.100 | 0.081 | 0.245 | **58%** |

### 4.3 Exp1b 渐进式 2D 骨架学习 — 关键结果

Exp1b 采用三阶段渐进训练（垂直线先验 → 渲染 loss 渐进接管 → 纯图像监督），是物理先验辅助纯 2D 训练的首次验证。

| 对比 | MNE (m) | 改善倍数 |
|------|---------|---------|
| Exp1b vs Exp1 原始 | 0.154 vs 0.313 | **2.0x 改善** |
| Exp1b vs MS-SCNF (3D GT) | 0.154 vs 0.059 | 2.6x 差距 |

**逐轴分析**：
- X/Y 轴误差（0.060/0.037 m）相对合理，接近有 3D GT 的水平
- **Z 轴误差仍占主导**（0.110 m，占比 72%），但比 exp1 原始（85%）有明显改善
- 物理先验（垂直线 + 长度守恒 + 光滑）部分缓解了深度歧义，但**无法根本消除**

**结论**：物理先验 + 渐进训练将纯 2D 训练的骨架精度提升了 2 倍，Z 轴误差从 85% 降至 72%。但 Z 轴（深度方向）仍然是主要误差来源，单视角的深度歧义是**固有的几何限制**。

### 4.4 Exp3 多视角深度歧义分析 — 详细结果

对已训练的 MS-SCNF（有 3D GT）模型，从正面/侧面/顶部三个视角分别渲染，分析骨架误差的轴向分布。

**骨架 GT 各轴变形量**：
- X range: mean=0.099m, max=0.288m（正面相机的深度方向）
- Y range: mean=0.115m, max=0.296m（侧面相机的深度方向）
- Z range: mean=0.446m, max=0.500m（垂直方向，变形量最大）

**模型预测各轴误差**：

| 方向 | 误差均值 (m) | 误差标准差 (m) | 误差最大值 (m) | 占比 | 该方向的相机可见性 |
|------|-------------|---------------|---------------|------|-----------------|
| X (正面深度) | 0.0373 | 0.0546 | **0.334** | **41.1%** | 正面相机看不到 |
| Y (侧面深度) | 0.0292 | 0.0446 | 0.266 | 32.2% | 侧面相机看不到 |
| Z (垂直) | 0.0242 | 0.0394 | 0.259 | 26.7% | 两个相机都能看到 |

**关键发现**：
1. **深度方向误差是固有且最大的**：即使在有 3D GT 训练的模型中，正面深度方向（X）误差也占 41.1%，最大单点误差达 0.334m
2. **误差排序与可见性完全对应**：看不到的方向误差最大 → 单视角深度歧义是不可回避的几何事实
3. **最大变形方向恰好是深度方向**：GT 骨架 Z 轴变形（0.446m）远大于 X/Y（0.099/0.115m），但 Z 不是深度方向所以误差反而最小；X 变形不大但作为深度方向误差最大
4. **推理：增加一个正交视角可以互补消除深度歧义**。正面相机看不到 X → 侧面相机能看到 X；侧面相机看不到 Y → 正面相机能看到 Y。两个正交相机理论上可约束所有轴

### 4.5 多视角自建模可行性分析

基于 exp3 的发现，参考 Chen et al. 2022（Full Body Visual Self-Modeling）使用 5 台 RGB-D 相机的方案，分析多视角在软体机器人上的可行性。

**方案对比**：

| 方案 | 相机数量 | 是否需要 RGB-D | 深度歧义 | 实现复杂度 |
|------|---------|--------------|---------|-----------|
| Chen 2022 方案 | 5 台 RealSense D435i | 是（需要深度图） | 无（多视角+深度） | 高（标定、同步） |
| 双视角 NeRF | 2 台普通 RGB 相机 | 否 | 基本消除 | 中（双目标定） |
| 单视角 + 物理先验 (exp1b) | 1 台 RGB 相机 | 否 | 部分缓解（72%） | 低 |
| 单视角 (exp1) | 1 台 RGB 相机 | 否 | 严重（85%） | 最低 |

**推荐方案**：**双视角 RGB 相机 + 体渲染**

理由：
1. 体渲染（NeRF 系）天然支持多视角训练，每个视角独立渲染、loss 累加
2. 双视角渲染 loss：`loss = MSE(render_front, GT_front) + MSE(render_side, GT_side)`，无需修改模型架构
3. 不需要 RGB-D 深度传感器（Chen 2022 需要），因为体渲染从多视角 2D 图像中隐式恢复 3D
4. 软体机器人是细长杆体，两个正交视角足以覆盖主要变形方向
5. exp3 数据证实：正面+侧面正交配置下，X/Y/Z 各有至少一个视角约束

**预期效果**：
- exp1b 已将 Z 误差从 85% 降至 72%（物理先验的贡献）
- 加入第二视角后，深度方向不再是盲区 → Z 误差预计降至 ~30% 以下
- MNE 预计从 0.154m 降至 ~0.08-0.10m，接近有 3D GT 的 0.065m

## 五、当前模型与原始设想的差距

### 5.1 保留了什么

| 原始设想 | MS-SCNF |
|---------|---------|
| 空间点坐标 + 驱动信号 → 可见度/密度 | ✅ 有这个路径 (forward) |
| 2D图像作为学习信号 | ✅ Phase 2 用渲染 loss |
| 体渲染框架 | ✅ OM_rendering |

### 5.2 改变了什么

| 原始设想 | MS-SCNF | 原因 |
|---------|---------|------|
| 隐式学习3D形态 | 显式输出骨架坐标 | 隐式学习搜索空间太大，不收敛 |
| 只用2D图像训练 | Phase 1 用3D GT坐标 | 2D渲染loss梯度太弱，无法训练骨架 |
| 网络自由发现结构 | 假设31节点链式骨架 | 软体机器人是细长杆，骨架先验合理 |
| 单阶段端到端 | 两阶段训练 | 先学骨架再学外观，更稳定 |

### 5.3 本质差异

**原始设想**: 模型是一个纯粹的隐式场 (implicit field)，网络自己决定"机器人长什么样"

**当前 MS-SCNF**: 模型是一个**半显式**表示：
- 骨架是**显式**的（直接输出 3D 坐标）
- 外观（密度/可见度）是**隐式**的（基于骨架距离的神经网络）
- 训练依赖仿真器的 **3D GT 监督**

这不是完全的"自建模"——机器人被告知了骨架在哪里。但密度场部分确实是从 2D 图像学到的。

### 方向 A: 纯 2D 自建模 — 2D 图像能否替代 3D GT？

#### 要回答的问题

> 去掉仿真器的 3D GT 坐标监督，仅用单/双相机 2D 图像，MS-SCNF 能学到什么程度的 3D 骨架？

这个问题决定了我们的方法是否真的是"自建模"。如果必须依赖 3D GT，那模型本质上是在做回归拟合而非从观察中学习。

#### 已有证据 (exp1, exp2)

**exp1 原始结果**：用 MS-SCNF 架构，Phase 1 不用 3D GT，直接用 2D 渲染 loss 端到端训练 50 epochs。

| 指标 | MS-SCNF (有3D GT) | exp1 (纯2D) | 差距 |
|------|-------------------|-------------|------|
| MNE | 0.0646 m | 0.3129 m | 4.8x |
| Tip Error | 0.1085 m | 0.5884 m | 5.4x |
| Z轴误差占比 | 28% | **85%** | 深度崩溃 |

**推理链条**：
1. Z 轴误差从 28% 暴涨到 85% → Z 是相机深度方向，单视角无法约束
2. GT 骨架的 Z 变形范围(0.446m)远大于 X(0.099m)和 Y(0.115m) → 大变形方向恰好是不可观测方向
3. 渲染 loss 的梯度路径：`2D MSE → OM_rendering → density MLP → dist_to_skeleton → skeleton positions → temporal`
   - 共 5 层间接映射，density MLP 的 softplus + exp 非线性导致梯度消失
   - 10000 条射线 × 48 samples 中只有 ~200 个点在杆附近有非零梯度（约 0.04%）
4. 结论：**单视角 2D 渲染 loss 本身不足以训练 3D 骨架**，深度方向需要额外约束

**exp3 多视角分析**：加载已训练的 MS-SCNF 模型，从正面/侧面/顶部三个相机视角分别渲染，分析骨架误差的轴向分布。

```
正面相机 (X轴): 看到的是 YZ 平面投影，X方向是深度
侧面相机 (Y轴): 看到的是 XZ 平面投影，Y方向是深度
顶部相机 (Z轴): 看到的是 XY 平面投影，Z方向是深度
```

结果：
- X 方向误差 (正面深度): 占 41.1%，最大 0.334m
- Y 方向误差 (侧面深度): 占 32.2%，最大 0.266m
- Z 方向误差 (垂直): 占 26.7%，最大 0.259m

推理：即使是有 3D GT 训练的模型，**深度方向的误差仍然最大**（41%）。这从另一面证实了单视角的深度歧义是固有的。

#### 改进实验 (exp1b) — 已完成

**假设**：如果加入强物理先验（骨架是垂直的、长度固定、光滑的），2D 渲染 loss 能否引导骨架收敛到正确位置？

**实验设计**：三阶段渐进训练（垂直线先验 → 渲染 loss 渐进接管 → 纯图像监督），共 50 epochs。

**实际结果**：

| 指标 | Exp1b 结果 | Exp1 原始 | MS-SCNF (3D GT) | 判定 |
|------|-----------|----------|----------------|------|
| MNE | **0.154 m** | 0.313 m | 0.059 m | ✅ < 0.2m，物理先验有效 |
| Z 轴误差占比 | **72%** | 85% | 28% | ⚠️ 有改善但未 < 50% |
| Z 轴误差 | **0.110 m** | 0.302 m | 0.014 m | ⚠️ 降至原来的 1/3 |

**结论判定**（对照原定标准）：
- MNE = 0.154m < 0.2m → **物理先验 + 渐进训练确实有效**，比 exp1 改善 2 倍
- Z 误差占比 72% > 50% → **深度歧义未被充分缓解**，单视角限制仍然存在
- MNE = 0.154m >> 0.065m → **纯 2D 单视角无法达到 3D GT 水平**

**推理链条（已验证）**：
- ✅ 初始化为垂直线 → 骨架起点在正确区域附近 → X/Y 轴误差合理（0.060/0.037 m）
- ✅ 渐进式混合 → 训练收敛，loss 在 10 epoch 后稳定

### 方向 B: 时序迟滞建模 — 软体机器人与刚性机器人的本质区别

#### 要回答的问题

> 软体机器人的粘弹性迟滞（加载/卸载路径不同）能否被时序编码器捕捉？HA-EMA 是否比标准 EMA 更好？

这是与所有现有自建模工作（Chen 2022, Shan 2024, Hu 2025）的核心差异。这些工作都假设驱动→变形是瞬时映射，忽略时序历史。

#### 为什么迟滞重要

```
刚性机器人: 施加扭矩 T → 立即产生确定的弯曲角 θ
  关系: θ = f(T)，与历史无关

软体机器人: 施加扭矩 T → 弯曲角取决于加载历史
  加载路径: T 从 0 增加到 T_max → θ₁
  卸载路径: T 从 T_max 减少到 0 → θ₂ ≠ θ₁
  差异原因: 粘弹性材料的分子链重新排列需要时间
```

如果不建模迟滞，模型无法区分"正在加载"和"正在卸载"这两种状态 → 预测在过渡过程中会出错。

#### 已有证据 (exp5 Part 1)

**仿真器迟滞验证**：在 PyElastica 中运行三角波驱动（扭矩从 0→0.3→0→-0.3→0 循环），记录 tip 位移。

```
三角波:
  扭矩  ─╱╲╱╲╱╲   (锯齿形)
  tip_x ─╱  ╲╱  ╲  (如果无迟滞，两条路径重合)
         ╲  ╱╲  ╱  (如果有迟滞，加载和卸载路径分开)
          ╲╱  ╲╱
```

结果（`sim_hysteresis_loops.png`）：
- 频率 0.5Hz: 可观测到迟滞环，加载/卸载路径不同
- 频率 1.0Hz: 迟滞环更宽（快速加载时粘弹性效应更明显）
- 频率 2.0Hz: 迟滞环继续增大

**推理**：仿真器确实模拟了粘弹性行为（PyElastica 的阻尼系数 DAMPING > 0）。这给了我们验证 HA-EMA 的物理基础。

#### 改进实验 (exp5 Part 2-3)

**HA-EMA 设计思路**：

标准 EMA 的问题：
```python
# 标准 MultiScaleEMA:
state_t = α * state_{t-1} + (1-α) * action_t
# α 是固定的 → 无论扭矩在增加还是减少，衰减率相同
# → 无法区分"正在加载"和"正在卸载"
```

HA-EMA 的改进：
```python
# HysteresisAwareEMA:
if action 在增加 (加载):
    state_t = α_load * state_{t-1} + (1-α_load) * action_t
    # α_load: 加载时"记住"多少历史
    # 如果材料在加载时响应快 → α_load 小 (快速跟踪)

if action 在减少 (卸载):
    state_t = α_unload * state_{t-1} + (1-α_unload) * action_t
    # α_unload: 卸载时"记住"多少历史
    # 如果材料在卸载时恢复慢 → α_unload 大 (慢 forgetting)

# 方向门控网络学习如何混合 α_load 和 α_unload:
gate = sigmoid(MLP([当前动作, 速度]))
α_dynamic = gate * α_load + (1-gate) * α_unload
```

**验证实验**：
1. 用 Standard EMA 和 HA-EMA 分别训练骨架预测器
2. 在**三角波测试数据**上评估（专门测试迟滞性能的数据）
3. 关键指标不是整体 MNE，而是：
   - **迟滞环面积误差**：预测的迟滞环面积 vs GT 的面积
   - **加载/卸载分支分别的误差**：是否有一个方向特别差
   - **相位滞后**：预测的响应是否比 GT 慢/快

**如何判断成功**：
- HA-EMA 的 MNE < Standard EMA 的 MNE → HA-EMA 确实更好
- HA-EMA 在三角波数据上的加载/卸载误差更均衡 → 迟滞被正确捕捉
- 学习到的 α_load ≠ α_unload → 网络确实学到了不同方向的衰减率
- 如果学习到的两组 decay rate 差异很大 → 迟滞效应确实显著

```bash
python scripts/experiments/exp5_hysteresis_analysis.py --gpu 0 --use_sim
```

**推理链条**：
```
假设: 软体机器人的粘弹性导致加载/卸载响应不同
  → 验证: 仿真器三角波实验是否显示迟滞环? ✓ 已确认
  → 预测: HA-EMA (方向依赖的衰减率) 应比标准 EMA (固定衰减率) 更好
  → 验证: 在相同数据上训练, HA-EMA MNE 是否更低?
  → 如果更低: 证明了时序编码需要方向感知 → 论文创新点成立
  → 如果无差异: 可能仿真器迟滞太弱, 或 4 个 EMA scale 已隐式捕捉
```

### 方向 C: 多相机系统 — 如何消除深度歧义

#### 要回答的问题

> 额外增加一个正交相机视角，能把纯 2D 训练的骨架精度提升多少？

#### 已有证据 (exp3 + exp1b)

**exp3 多视角分析**揭示了深度方向误差的严重性（详见 4.4 节）：

```
          Z (up)
          ↑
          |   ● ● ● ● ... (31个骨架节点)
          |  ╱
          | ╱  杆体
          |╱
          +--------→ X (正面相机方向)
         ╱
        ╱
       ↓
      Y (侧面相机方向)

正面相机: 从 X 轴方向看 → 看到 YZ 平面投影
侧面相机: 从 Y 轴方向看 → 看到 XZ 平面投影
```

**模型预测各轴误差**（已训练的 3D GT 模型）：
- X 误差: 41.1%（正面相机的深度 → **这个方向看不到**，最大单点 0.334m）
- Y 误差: 32.2%（侧面相机的深度 → 这个方向也看不到）
- Z 误差: 26.7%（两个相机都能看到 → 约束最强）

**exp1b 验证了物理先验的贡献但确认了单视角的上限**：
- 物理先验将 Z 误差从 0.302m 降至 0.110m（改善 63%），但 Z 仍占 72% 的总误差
- 说明：**单视角 + 物理先验只能缓解但无法消除深度歧义**

**多视角自建模的可行性论证**：
1. 深度方向（相机看不到的方向）误差占 41% → 单视角最大的弱点
2. 如果增加一个正交相机（Y轴方向），那么 X 轴不再是深度方向 → X 误差应大幅下降
3. 两个正交相机：X 轴是侧面相机的投影方向，Y 轴是正面相机的投影方向，Z 轴两者都能看到
4. **理论上所有轴都有至少一个视角的约束** → 深度歧义应基本消除
5. 参考 Chen et al. 2022：5 台 RGB-D 相机实现刚性机器人自建模，但**我们只需 2 台普通 RGB 相机**（体渲染隐式恢复 3D，不需要深度图）

### 方向 D: 仿真到真实迁移 — 域随机化能否提升鲁棒性？

#### 要回答的问题

> 在仿真训练时加入图像噪声/亮度/背景随机化，模型在真实世界图像上的表现能提升多少？

#### 已有证据与 bug 分析 (exp4)

**exp4 原始结果有问题**：

| 配置 | Clean MNE | Noisy MNE (σ=0.2) |
|------|-----------|-------------------|
| Baseline (无DR) | 1.220956 m | 1.220956 m |
| DR 训练 | 1.108048 m | 1.108048 m |

所有噪声水平的 MNE **精确到小数点后6位完全相同** → 这不正常。

**bug 原因分析**：
```
原始评估逻辑:
  1. 加噪 → gt_img_noisy = randomizer(gt_img)  # 对 GT 图像加噪
  2. 预测骨架 → pred_skeleton
  3. 计算误差 → MNE = dist(pred_skeleton, gt_3d_positions)

问题: MNE 是骨架的 3D 坐标误差, 与图像噪声无关!
  - 图像噪声影响的是渲染质量 (PSNR/MSE)
  - 不影响骨架预测 (骨架预测只依赖 action_window)
  - 所以 MNE 在所有噪声水平下完全一样
```

**正确做法**：评估渲染质量而非骨架精度。噪声应加在模型的输入（测试图像）上，测量的是渲染出的图像在噪声条件下的质量。

#### 改进实验 (exp4b)

**修复后的实验设计**：

```
训练: 3种配置对比
  - no_dr:   训练图像不加噪声 (baseline)
  - dr_light: 加轻微噪声 (σ=0.03, 亮度±10%, 背景0-5%)
  - dr_heavy: 加强噪声 (σ=0.1, 亮度±30%, 背景0-20%)

评估 (修复后):
  对每个模型, 在不同噪声水平的测试图像上评估渲染质量:
  - PSNR (dB): 渲染图与GT图的峰值信噪比, 越高越好
  - MSE: 渲染图与GT图的均方误差, 越低越好

  同时评估骨架精度 (MNE), 但这应该是恒定的 (与噪声无关)
```

**如何判断成功**：
- PSNR 随噪声增大而下降 → 证明确实受噪声影响（与原 exp4 不同）
- DR 训练的模型在噪声条件下的 PSNR 下降更少 → DR 提升了鲁棒性
- 但 Clean PSNR 可能略低 → DR 的代价是干净条件下的精度略降

**推理链条**：
```
假设: 真实世界的图像与仿真不同 (噪声、光照、背景)
  → 在仿真中随机化这些因素, 模型应学到忽略它们
  → DR 训练的模型在噪声图像上的 PSNR 应更高
  → 如果 DR_heavy 在高噪声时最好 → 证明了 DR 的价值
  → 如果 DR_heavy 在 Clean 时最差 → DR 的代价是精度略降
  → 需要找到合适的随机化强度
```
