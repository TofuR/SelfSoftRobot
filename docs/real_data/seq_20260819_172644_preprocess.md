## 8. GTObserved与OpenLoop训练

### 8.1 冒烟测试和超参数选择

在GPU 2逐档实测batch，而不是按显存上限盲目放大。模型正确探测
`raw=6D -> [0,1,3,5] -> 4D`，所有档均无NaN：

| batch | batch/epoch | GT首轮时间 | GT首轮total loss |
|---:|---:|---:|---:|
| 64 | 154 | 124 s | 0.00565 |
| 128 | 77 | 64 s | 0.00729 |
| 256 | 39 | 32 s | 0.00877 |
| 512 | 20 | 18 s | 0.00976 |
| 1024 | 10 | 12 s | 0.01026 |

更大batch虽然扫数据更快，但每轮更新次数锐减，首轮几乎没有充分学习。按单位墙钟loss下降和
优化步数的折中，batch=128是本数据的拐点。纯闭环OpenLoop在batch=128下实测约69秒/epoch、
无NaN且显存充足，因此正式配置不用DDP；本模型只有243,564个参数且40步递推串行，多GPU
同步的通信开销很可能大于收益。正式运行统一使用GPU 2：训练进程持续运行；每当第10、20、
30……个epoch的checkpoint出现，后台watcher会在同一张卡上并发执行周期验证与绘图，不会
暂停训练。两进程在约13秒的验证期间会共享GPU算力，训练吞吐可能短暂降低，但不值得为此
增加第二张GPU和进程管理复杂度。

本轮同时修复了已有`--seed`参数只解析但不生效的问题：现在会设置Python、NumPy和PyTorch
随机种子，并把seed写入实验`config.json`。正式会话启动日志已确认
`Reproducibility seed: 20260821`。

epoch是上限而不是为了耗满固定时间。正式配置为GT最多60轮、OpenLoop最多240轮，训练预算
比例1:4；GT约1.1小时，OpenLoop约4.6小时，连同评价预计5.8–6.2小时。OpenLoop从本次GT
best checkpoint热启动；前20轮保持teacher forcing=1，随后220轮使用40步纯闭环训练
（`tf_anneal_epochs=40`、`staircase`）。是否足够以每10轮的val像素误差、形态误差和
`drift_by_k`是否进入平台为准，而不是以墙钟时间为准。

每5个epoch保存三类中间产物：`model/current_model.pt`覆盖为最近模型，
`checkpoints/model_epoch_XXXX.pt`保留不可覆盖的历史权重，
`checkpoints/training_state_latest.pt`额外保存optimizer、scheduler、epoch和best loss。
`best_model.pt`每次loss创新低立即更新，阶段结束另存`final_model.pt`。因此即使进程中断，最多
损失5个epoch，不会只剩空目录。

每10个epoch，GPU 2会在500帧val上评价“截至该epoch的best模型”，同时保存定量CSV/曲线、
原始照片+SAM2 mask+GT/预测骨架叠图和`montage.png`。GT阶段先做像素评价；GT结束后生成同
序列NDI诊断仿射，OpenLoop周期评价再同时输出毫米和`drift_by_k`。周期结果按epoch保留，最终
仍跑全量val；训练中断不会丢掉已经完成的验证证据。

正式启动前的GPU 2训练/GPU 3验证运行已完成一次端到端自动产物检查。epoch 10自动生成了
`periodic_gt/epoch_0010/summary.txt`、`per_frame.csv`、误差曲线、16张真实照片叠图、
`overlay/montage.png`和`overlay/error_plot.png`；tip均误差为2.422 px、全节点均误差为
1.230 px。该验证运行保留在
`train_log/real_pipeline/seq_20260819_172644_n15_sam2/20260821_b128_gpu2_eval3/`，状态中的
`exit=130`表示完成链路检查后为迁移到单GPU而主动停止，不是训练故障。

迁移后的正式单GPU运行也已在epoch 10完成同样检查。训练和watcher都绑定GPU 2，训练进程
在定量评价及叠图期间继续推进；`latest.json`记录整套周期评价耗时13.142秒。结果保存在

### 8.2 为什么先GT再OpenLoop

两种模式使用同一网络结构和同一个状态转移问题：

```text
z_t, s_hat_t = F(action_history_t, state_input_(t-1), z_(t-1))
```

差别只在`state_input`：GTObserved每一步都输入真实`s_(t-1)`，所以先学习稳定的局部单步
动力学，不让早期随机误差沿40步累计；OpenLoop只在episode开始使用一次真实锚点`s_0`，后续
把自己的`s_hat_(t-1)`喂回模型，并对整段40步预测做dense loss和BPTT。这一步训练模型处理
自己造成的分布偏移和误差累计，才对应实际“观察一次、连续预测K步”的部署方式。

旧训练入口已经支持OpenLoop从最新、且`action_dim`匹配的GT checkpoint热启动；但旧操作是
两条独立命令，并不会保证先为当前数据新跑GT。若已有合适GT，你看到的操作可能是直接执行
OpenLoop；若没有匹配checkpoint，代码也允许冷启动。本次新脚本明确串成：

```text
当前数据GT预训练 -> 本次GT best权重 -> OpenLoop rollout训练 -> 两者独立评价
```

GT是训练底座和每步观测精度上界，不是最终部署方案；最终控制与论文主线仍是OpenLoop。

## 9. 16 mm尺度下的前向模型评价与离线规划计算

### 9.1 本序列图像尺度

当前旧QC表尚未包含主体中段宽度，尺度解析器使用有效帧`tip_width_px`中位数：

```text
robot_diameter_mm = 16.000 mm
robot_diameter_px = 20.542 px
mm_per_px          = 0.778874 mm/px
```

以后重新执行骨架转换时会直接测量并保存`body_width_px`，评价优先使用主体中段宽度。该换算
用于当前固定相机、平面运动区域内的误差估计；NDI的末端毫米值继续作为独立三维评价。

最终best模型在本序列val上的前向预测结果如下。表中所有误差都由“模型预测骨架”与
“数据集记录骨架GT”逐节点比较得到：

| 前向评价模式 | tip预测误差均值 | 全节点预测误差均值 | 输入与比较方式 |
|---|---:|---:|---|
| GTObserved | 2.046 px ≈ 1.594 mm | 1.059 px ≈ 0.825 mm | 每步输入数据集上一帧真实骨架，预测下一帧并与记录GT比较 |
| OpenLoop窗口全步 | 4.064 px ≈ 3.165 mm | 2.449 px ≈ 1.908 mm | 40步窗口中汇总`k=1..40`的所有预测行；每窗口只输入一次真实起点 |

OpenLoop逐帧表的第0行是真实骨架锚点，`is_prediction=0`；本次统计使用其余2475行
`is_prediction=1`的前向预测。锚点行用于初始化rollout，不产生可与GT比较的预测值。
因此`OpenLoop窗口全步·全节点`是对窗口中不同深度的预测先做15节点平均，再对所有
有效预测帧汇总；`OpenLoop第40步·全节点`只取距真实锚点正好40步的终点，并对8个评价
起点汇总。两者使用相同的40步上限，统计的步位范围不同。

OpenLoop的40步前向rollout评价使用数据集记录的未来驱动序列。`step 40`表示模型从真实起点
连续自回归40步后，将第40个预测骨架与数据集中同一记录驱动序列下的
第40个记录骨架比较。数组索引为39，图表步数为40：

```text
step 40 mean-node error = 3.708 px ≈ 2.888 mm
final drift             = 1.732x
prediction horizon at 2 mm        = 25 steps
prediction horizon at 3 px        = 31 steps  (≈2.34 mm)
prediction horizon at 4 mm / 5 px = 40 steps
```

部署manifest把这些前向预测阈值转换为`K_safe`门限，用于限制一次规划所依赖的模型rollout长度。
`K_safe`描述前向模型在记录动作序列上的可信视野，不代表实物控制精度或控制成功率。

### 9.2 给定完整形态后的离线逆规划计算

当前模型和`real_validation`已经形成以下可执行链：

```text
实时图像 -> SAM2同合同分割/15节点骨架 -> anchor(s0 + H步applied6)
目标15节点骨架 + 圆障碍 -> OpenLoop shooting逆规划
4维独立kPa序列 -> [ch0,ch1,ch1,ch3,ch3,ch5]六路展开
predicted_states.npz + plan.json -> Preflight -> Arm -> 逐拍ACK执行
执行后重新拍照锚定 -> 下一段规划
```

滚动重规划时，GUI用当前anchor历史初始化H步缓冲，随后以每拍ACK `applied6`替换最旧动作；
新相机anchor读取该缓冲，并把`initial_action6`同步为最近实际压力。下一段动作由真实压力状态
继续，首拍rise/fall约束与硬件状态一致。

目标骨架可来自一帧已采集的真实骨架、JSON或GUI按`tip -> base`点出的15个节点。真实录制帧
证明该目标形态曾在数据采集动作下出现；逆规划器产生的是另一条候选动作序列，其实际结果
需要真机执行后重新观测。规划器同时优化所有15个节点；两段机器人仍作为一条耦合骨架进入模型。

离线规划产物中的量按以下来源解释：

- `start_to_target_shape_distance`：两个数据集记录骨架之间的形态差异；这是目标位移。
- `predicted_terminal_target_residual`：学到的前向模型对候选动作序列计算出的终态目标残差；
  这是规划器内部估计。
- `execution.csv`中的Mock ACK：动作序列通过执行器、时序和安全合同；它不包含机器人形态观测。
- 真机控制结果：执行候选动作后，用相机重新提取15节点骨架，再与目标比较得到。

`metadata.loss_curve`记录规划器在120次梯度优化中计算的复合目标函数，由终态、路径、
单调性、动作平滑和障碍约束项组成。该曲线表示候选动作在学习前向模型内的优化进度；
实物执行后的目标残差由新拍摄的骨架计算。

第120帧到第160帧的旧算例中，两个记录骨架的目标位移为
`17.685 px ≈ 13.775 mm`；模型预测候选动作的终态目标残差为
`11.315 px ≈ 8.813 mm`。这两个量没有共同的实物执行终态，不能相减后称为控制误差下降。
40个Mock ACK只记录命令链通过。

为覆盖更显著的形态差异，在val中先过滤弧长5–95%范围、有限节点和base偏移不超过5 px的帧，
再搜索全节点平均距离最大的骨架对：

```text
起点: val index 332  / 原始 frame 10236（弯曲形态）
目标: val index 1183 / 原始 frame 11087（接近伸直形态）
base位移:                    0 px
记录骨架间全节点平均形态差异: 36.687 px ≈ 28.574 mm ≈ 1.79D
记录骨架间末端位移:          113.340 px ≈ 88.278 mm ≈ 5.52D
```

在`K=40`、单起点、120次迭代下，规划器为这组目标生成了通过Preflight的四维动作序列，
前向模型预测的终态目标残差为`31.348 px ≈ 24.416 mm`。该目标在原采集中相隔851拍，
一次40步模型视野只覆盖候选动作的第一段。这里记录的是模型内规划计算；实物控制终态需要
真机下发计划后重新采集骨架。

这组场景的目标容差是`2 px`，因此`31.348 px`的模型预测终态未达到目标。
`Preflight=PASS`表示压力范围、rise/fall、时序、通道映射和部署合同通过安全检查。
该组合用于检查数据集的大幅形态范围。

另外在每对帧间隔不超过40拍的条件下搜索，得到一组实际34拍内发生过的大幅形态转换：

```text
起点: val index 395 / 原始 frame 10299
目标: val index 429 / 原始 frame 10333
记录骨架间全节点平均形态差异: 32.802 px ≈ 25.548 mm ≈ 1.60D
记录骨架间末端位移:          97.509 px ≈ 75.948 mm ≈ 4.75D
base位移:                              0 px
```

将该区间真实记录的34拍动作输入OpenLoop前向模型，第34步预测与记录目标的全节点
平均误差为`3.110 px ≈ 2.422 mm`，末端预测误差为`6.167 px ≈ 4.803 mm`。这是该区间的
前向模型复现结果。

规划器根据当前骨架与目标骨架的最大节点差距选择K。该目标的差距为`95.509 px`；
部署合同中K=4/8/20/40的实测p95最大节点位移分别为`30.043/42.727/54.207/56.053 px`。
目标超出40步表内容量，所以自动策略选择认证上限`K=40`。原记录中的34拍间隔只用于说明
该形态转换曾经发生，不参与新候选动作的规划步数决策。

以`auto K=40, 400 iter, 3 restarts`运行shooting搜索，模型预测终态目标残差为
`10.352 px ≈ 8.063 mm`，高于`2 px`目标容差。当前前向模型可以沿记录动作复现这段形态转换，
shooting动作搜索尚未找到同等质量的候选序列。该逆规划算例的结论是搜索未达标，下一步应先改进
初始化、动作参数化和优化目标，再进入真机执行。
